    • What Problem Does It Solve?

    Small businesses often rely on manual confirmation for mobile payments, making it hard to track who paid, when they paid, and what the payment was for.

    This project explored how a simple web application can generate payment links and automatically produce receipts once a transaction is completed.

    My Approach

    I focused on building a clean, semantic front-end paired with a basic API-driven workflow that mirrors real payment systems.

    The project emphasized:

    • Semantic HTML for clarity and accessibility
    • Understanding HTTP requests and JSON responses
    • Testing API behavior using Postman before writing code
    • Using Git properly to track progress and changes

    The Hardest Thing I Learned

    The hardest lesson was realizing that frontend interfaces are tightly coupled to backend assumptions.

    I learned that unclear API contracts lead to fragile interfaces, and that testing endpoints early saves time later.

    Next Steps

    I plan to iterate on this project by:

    • Adding a backend to handle payment processing and receipt generation
    • Improving the UI/UX based on user feedback
    • Implementing error handling for failed transactions
    • Exploring how to integrate with real payment APIs in the future
